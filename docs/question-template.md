# 提问规范模板

本项目把提问规范前置到写代码之前。提交 issue、向 AI 请求改动、或在群里请求他人帮助时，必须使用下面的四段结构。缺一段就先补齐，再进入开发或回复。

## 使用原则

1. **具体标题**：让读者第一行就知道问题对象和症状。
2. **问题背景**：让读者知道目标、环境和已经尝试过什么。
3. **最小复现**：让读者用最少步骤看到同一个现象。
4. **预期结果**：让读者知道怎样才算解决，而不是只表达“坏了”。

## 模板

```markdown
## 标题

<一句话说明对象 + 具体症状>

## 问题背景

- 目标：
- 环境：
- 已尝试：

## 最小复现

1.
2.
3.

## 预期结果

-
```

## 示例：好标题与坏标题

| 质量 | 标题 |
| --- | --- |
| 好 | `搜索 satnaing/shadcn-admin 后时间地层不显示 2024-12 提交数` |
| 坏 | `时间轴有问题` |

## 示例：完整提问

```markdown
## 标题

搜索 satnaing/shadcn-admin 后时间地层不显示 2024-12 提交数

## 问题背景

- 目标：验证 CodeStrata 的月度聚合在真实仓库上正确显示活跃峰值。
- 环境：Windows 11、Chromium 最新版、本地静态服务器 http://127.0.0.1:4175、未登录 GitHub API。
- 已尝试：确认 satnaing/shadcn-admin 的 2024-12 在 GitHub API 返回 54 次提交；清空 localStorage 后重试一次。

## 最小复现

1. 启动静态服务器并打开首页。
2. 输入 `satnaing/shadcn-admin`。
3. 点击“发掘”。
4. 查看 2024 年地层。

## 预期结果

- 2024-12 的地层显示 54。
- 点击该月后详情面板显示 54 和活跃贡献者信息。
- 数据来源显示 GitHub 实时数据与检索时间。
```

## 提交前检查

- [ ] 标题具体到对象和症状
- [ ] 背景包含目标、环境和已尝试
- [ ] 复现步骤是可重复的最小步骤
- [ ] 预期结果可观察、可判定
